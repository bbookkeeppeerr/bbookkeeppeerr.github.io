Our hero awakens

In which our hero fights against the AI overreach of his day-to-day job to remember the simple joy of making something for themselves

When making things for myself I have some simple rules

Use raw javascript when possible

Most of my daily tasks involve typescript, between the transpiling from typescript to javascript, and the inevitable minimization afterwards that most websites will do by default, the raw javascript is a lot harder to decompile and read.

Quite frankly, I enjoyed when I could read a website that was doing something cool, look at the source and see how it did it, to try and figure out how I would do something similar. This is something that has been disappearing for a while, and since when I make these tools I'm not too concerned about whatever a business claims is good for it's search rank, I would rather pay it forward and start with the idea that someone might want to see how this works under the covers

(Some would say that I should have spent some time finding a css theme when investigating other peoples websites, but I didn't, and now that they've all turned into div soup from whatever standard library is to de-jour of the day, I'm not going to find it)

Avoid a complex release pipeline

So whilst I am actually a fan of things like eslint and prettier, if I need them for the local projects then it's probably overkill. I do have some formatting rules I keep to (which I get from my editor rather than a multi-step build proccess) and since I am not working with multiple people to get even the simplest thing running and co-ordinated, I want to try and do without

With all of that said, lets get started

Youtube thumbnail viewer chrome extension

Why this? I started drawing during the years of the great plague (i.e. covid). I'm still at the stage of copying things rather then coming up with things from my mind, and I do use youtube as a source of ideas.

Of course, it's easier if you can see the image in the entire screen, I could have tried and find an existing plugin, but I wanted to see if I could make my own

VSCode setup

Even though I'm not setting up a full release pipeline, I do have a couple of things installed to make vscode intellisense keep some level of sanity

chrome manifest checker makes sure that the manifest we make is valid

ESLint just because I don't want to set up a full pipeline, I still like ESLint and having a seet of default rules makes things easier

Implementation

This is old ground obviously, so https://stackoverflow.com/questions/2068344/how-do-i-get-a-youtube-video-thumbnail-from-the-youtube-api described the 5 different possible urls that a video whould have for it's thumbnail. And yes one of the reasons I didn't just make a bookmark to convert the url is that there are 5 different possibilities, and I wanted to always get the highest res image I could

Start with the npm init to get the package.json, and create a manifest (this isn't my first plugin, so I had a simple manifest.json file already) - manifest definition can be seen on Chrome manifest reference

The important part is adding the background.js link option in the manifest, that's where the code will be running.

chrome extensions have 3 different ways of running things - simplified below:

  • popup - this is used if the extension itself has it's own unique window - I could have used this, but I didn't think I needed that, just wanted an action when I clicked on the extension button
  • context - runs within the web page itself, if I was manipulating the dom to add the button to the video, or if I needed to use an internally authed api to get the url path, this is what I would have used
  • background service worker - this runs as a service worker, it doesn't have access to the site + dom, but does have access to some top-level browser functionality (like tabs and their urls in this case). Script sections can only be triggered by events, which is fine for what I needed

there are better descriptions on how chrome extensions service workers work in the official documentation

The actual code is in background.js file, but the important parts

  • adding in @types/chrome as a devDependancy, and adding /// <reference types="chrome" /> as a comment at the top of the file so intellisense would work
  • chrome.action.onClicked.addListener() - this is the event that occurs when the extension icon is clicked, and it includes the current tab, which I could then get the url from
  • a sorted list of the image names and resolutions, so I could go through them in order and return the first one that returned successfully

Conclusion

Obviously, there are plenty of youtube related helpers in the chrome app store, and I could have grabbed any one of them. There are external sites as well that would do it. And that's fine. You could even argue that I've not really completed this (it won't work for youtube shorts for example, which is something I try not to use anyway and block somewhat religiously). And yes I should make actual icons

But here's the thing - it doesn't really matter. The skill being exercised is how to make a tool to make a small part of what I need to do in the browser easier. This is something I used to enjoy doing for work (before 'just type it into claude, who needs to access the website anymore anyway' became the normal answer) - making small tools like this to make our lives easier.

Anyway, that's all for now
